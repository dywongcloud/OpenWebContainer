Symptom
  The stack a program catches carries no code where host node 24.15's does. `Buffer.from(1)` caught
  answers `TypeError: The first argument must be of type string or an instance of Buffer,
  ArrayBuffer, or Array or an Array-like Object. Received type number (1)` on this container and
  `TypeError [ERR_INVALID_ARG_TYPE]: The first argument must be of type string or an instance of
  Buffer, ArrayBuffer, or Array or an Array-like Object. Received type number (1)` on host node
  v24.15.0, and the same is true of `Buffer.alloc(-1)` (`ERR_OUT_OF_RANGE`),
  `require('net').connect({ port: 'x' })` (`ERR_SOCKET_BAD_PORT`), `assert.ok(false)`
  (`ERR_ASSERTION`), `process.kill(pid, 'NOPE')` (`ERR_UNKNOWN_SIGNAL`) and
  `util.parseArgs({ args: 'nope' })` (`ERR_INVALID_ARG_TYPE`). The code is on the error as `code`,
  and the uncaught report already wrote `[<CODE>]` in the line it opens with, so the gap is the
  string `err.stack` answers and nothing else. Measured by the lane that closed
  owc-buffer-from-report-sentence-and-banner at cfdfe2e and left this unfiled: buf-from-probe,
  probe-alloc and probe-net differ before and after that fix, and what changes in them is the stack's
  own text.

Cause
  packages/core/src/process/executors/node/runtime/guest/globals.ts built the line a stack opens
  with out of the name and the message alone. Host node gets that line from the error's own
  toString, and the factory internal/errors.js builds every error it registers with answers
  `${this.name} [${key}]: ${this.message}` -- which is why `err.name` still reads the plain
  `TypeError` and `Error.prototype.toString.call(err)` still reads `TypeError: ...` with no code
  there, and why an error a program built and gave a code of its own and the ENOENT of a file that
  would not open carry no brackets either: neither is one that factory made. util-assert.ts already
  wrote that line into the report from the same two tests, the ERR_ prefix and the __owcRaised mark
  globals.ts keeps on every error it builds, and the stack's own header asked neither.

Fix
  packages/core/src/process/executors/node/runtime/guest/globals.ts
    stackHeaderOf -- the line a stack opens with carries the code in brackets behind the name when
    the error is one this container raised with one of node's own codes, the same ERR_ prefix and
    __owcRaised the report already asks. Nothing else moves: the name the error answers, the
    toString Error.prototype gives it, the frames behind the header, the internal sites, the ESM
    file:// names and the columns are the ones they were.
