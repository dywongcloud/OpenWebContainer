owc-worker-share-env-symbol-not-registered resolved witness-e94e79cb2c34a25e 2026-11-02T01:33:20Z

Symptom
  String(worker_threads.SHARE_ENV) is 'Symbol(nodejs.worker_threads.SHARE_ENV)'
  on both sides, but SHARE_ENV === Symbol.for('nodejs.worker_threads.SHARE_ENV')
  is true on host node v24.15.0 and false in the container: the container's was a
  fresh symbol made with Symbol() over the same words, so a symbol a program
  looks up in the registry -- from another realm, another bundle, or a value
  handed in -- never matched it.

Fix
  packages/core/src/process/executors/node/runtime/guest/modules/child.ts: the
  SHARE_ENV export is now CP_SHARE_ENV, made once at module scope with
  Symbol.for('nodejs.worker_threads.SHARE_ENV'), so the value the module exports,
  the value the Worker constructor compares opts.env against, and the value a
  second require of the module hands out are the one registered symbol. The
  description is unchanged, so String(SHARE_ENV) still reads
  'Symbol(nodejs.worker_threads.SHARE_ENV)'. The same symbol is what row
  owc-worker-share-env-not-shared keys the shared environment group on.
