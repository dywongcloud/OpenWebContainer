Row: owc-builtin-error-frame-not-internal

Symptom
  An error raised inside a builtin is reported at the caller's line, where host node 24.15 reports the
  internal site. `new Blob(1)` on the host opens with `node:internal/blob:148` over
  `      throw new ERR_INVALID_ARG_TYPE('sources', 'a sequence', sources);` and a caret, and its first
  frame is `    at new Blob (node:internal/blob:148:13)`; this container opened on `/app/main.js:1`
  over the program's own line and named `    at Object.<anonymous> (/app/main.js:1:1)` as its first
  frame. The same for `new File()` (`node:internal/file:64`, `at new File (node:internal/file:64:13)`),
  `Buffer.from(1)` (`node:buffer:362`, `at Buffer.from (node:buffer:362:9)`),
  `fs.readFileSync` of a file that is not there (`node:fs:561`, `at Object.openSync (node:fs:561:18)`
  and `at Object.readFileSync (node:fs:445:35)`) and an accessor reached through its descriptor
  (`node:internal/blob:230`, `at get size (node:internal/blob:230:13)`). Observed by the lane that
  closed owc-blob-file-ctor-no-validation and deliberately left it unfiled.

Cause
  The error a builtin raises is built inside the guest, so the frames the engine gives it are the
  frames of the guest's own bootstrap, and the renderer in globals.ts takes those out -- which leaves
  the caller's frame as the first one of the trace, and leaves the host's report, which reads the file
  and line out of that first frame, pointing at the program. Host node names a builtin's own frame
  because V8 names the frame of a script it compiled from its own internal source
  (src/node_builtins.cc names it `node:` + the builtin's id), and it prints that source's line under
  the banner because the throw site of the Message is the internal one and not the caller's.

Fix
  packages/core/src/process/executors/node/runtime/guest/buffer-fs.ts
    internalSiteOf, standing outside the two factories because both raise, puts the frames host node
    writes in front of the caller's: the builtin's own file, line and column under the name node names
    it there. It is wired to the raise sites of the Blob constructor (sources, the options dictionary
    and `options.endings`), the File constructor (its missing arguments), Buffer.from,
    fs.readFileSync's ENOENT -- two frames, the open that failed in front of the read that asked -- and
    the four accessors of the two classes, which now refuse a `this` that is not one of them with
    ERR_INVALID_THIS as the host does. A `.call` or `.apply` a caller reached the builtin through is
    dropped: node's own stack names no native frame there.
  packages/core/src/process/executors/node/process.ts
    NODE_INTERNAL_SITES holds, for each site a frame names, the file, line, column and line of source
    the report prints, and the branch scriptFailureText gained prints that banner -- the builtin's own
    file, its source line and a caret under the throw -- instead of reading the caller's. An error
    node builds in internal/errors is thrown from there and attributed to the builtin that asked for
    it, so `new Blob(['ab'], 5)` keeps the frame `at new Blob (node:internal/blob:150:5)` and the
    banner `node:internal/errors:542` over `      throw error;`.
  Pushed as 4eb925e66f80917761d631acd9937a763d450025, built on origin/main with a temporary index.
