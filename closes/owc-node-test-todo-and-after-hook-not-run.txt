Symptom
  A todo test's body never ran here and the module's own after hook never ran behind it: one
  todo test printed HOOKLOG ["[before]"] where host node v24.15.0 prints
  ["[before]","todo body","[after]"], and it was marked "⚠ todo (0ms) # TODO" where the host
  marks a todo that held "✔ todo (0.223375ms) # TODO". A suite registered last, and a test that
  was skipped, left the after hook unrun for the same reason.

Cause
  runTest short-circuited every todo before its body was called, and runAll ran the module's
  after hook only as the tail of the last test -- so a suite registered last, a test that was
  skipped and a todo all left it unrun.

Fix
  packages/core/src/process/executors/node/runtime/guest/modules/pure-b.ts
    runTest keeps the short circuit for a skip alone, so a todo is called with the hooks around
    it: one that held takes lineTodoOk and is counted a todo, one that did not keeps the warning
    sign, joins the failures and is counted a todo rather than a fail, so its run still ends on
    0 -- which is what the host does with a todo that does not hold. runAll runs the module's
    after hook once behind its whole collection, whatever kind the last item is, and lets a hook
    that throws keep the report.
