Symptom
  `trace_events.createTracing()` with no argument returned a tracing object in the
  container -- `Object.keys` of it `["categories","enabled"]`, its `categories` the
  empty string -- where host node v24.15.0 raises `TypeError: The "options"
  argument must be of type object. Received undefined`, and
  `createTracing({ categories: [] })` returned one too where the host raises
  `TypeError: At least one category is required`. Everything else on the module
  agreed: the export keys, the category list, `enable()`, `disable()` and
  `enabled`. Readme.md recorded `node:trace_events` only as a module that once
  did not resolve.

Fix
  packages/core/src/process/executors/node/runtime/guest/modules/pure-b.ts:
  `createTracing` now validates what it is handed in node's own order -- an
  options object, then an array, then an array of strings, then one that is not
  empty -- and refuses it with the host's own `TypeError`, message and `code`:
  `ERR_INVALID_ARG_TYPE` for the options object and for a `categories` that is
  not an array or holds something that is not a string, and
  `ERR_TRACE_EVENTS_CATEGORY_REQUIRED` for an array of no categories. The
  message's `. Received ...` clause is node's own spelling of the value. The two
  exports of the module, the joined category string, `enable()`, `disable()` and
  a second `disable()` are unchanged.
