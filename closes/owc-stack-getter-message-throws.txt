Resolution
  An error whose message or name getter throws is no longer swallowed. Reading err.stack
  propagates the error the getter threw, with node's four stack-preparation frames ahead of
  the caller's; util.inspect of that error answers '[object Error]'; and an uncaught error
  with no readable name or message gets the --trace-uncaught hint and the version trailer
  alone. The five getter cases and util-inspect agree with host node v24.15.0 on stdout,
  stderr and exit code.

Cause
  packages/core/src/process/executors/node/runtime/guest/globals.ts caught the getter's
  throw in stackHeaderOf and went on with a bare 'Error' header, so the run stayed alive
  with status 0. util-assert.ts read err.name and err.message without a guard. Host node
  24.15 lets the throw leave err.stack (V8 has called Error.prototype.toString through
  prepareStackTrace), reports the thrown error, and exits 1.
