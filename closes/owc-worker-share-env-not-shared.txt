owc-worker-share-env-not-shared resolved witness-e94e79cb2c34a25e 2026-11-02T01:33:20Z

Symptom
  The parent sets process.env.OWC_PROBE = 'from-parent', starts
  new Worker(worker.js, { env: SHARE_ENV }), and the worker reads the probe back
  and writes process.env.FROM_WORKER = 'yes'. After the worker exits the parent
  reads 'yes' on host node v24.15.0 and null in the container: the environment a
  SHARE_ENV worker was given was a copy per thread, not the one object the
  option's name promises.

Fix
  packages/core/src/process/executors/node/runtime/guest/modules/child.ts: the
  Worker constructor opens (or joins) one shared environment group when
  opts.env === CP_SHARE_ENV and hands the group's id to the thread in its ipc
  data; the worker bootstrap installs a proxy over process.env for that group,
  installed after the bootstrap has taken its own two keys out of the
  environment. A read refreshes from the host's copy, a write and a delete go
  through shared.envSet / shared.envDelete and are published back with
  host.setEnvJSON, so a child this process spawns later inherits what
  process.env.X = v has always published.
  packages/core/src/process/executors/node/runtime/capabilities/shared.ts: the
  host half -- envCreate, envRead, envSet, envDelete over one group of pairs the
  host holds. Two container processes share no heap, so the host is the only
  place one copy can live, the same place a SharedArrayBuffer keeps the bytes a
  wait is left on. A group is never dropped: a write a thread made has to still
  be there for its parent to read after the thread has gone.
