CHANGED

  packages/core/src/process/executors/node/runtime/guest/buffer-fs.ts

  fs.watch reads recursive out of the options it was handed -- the boolean true and
  nothing else, as on a host -- and hands it to the watcher. watchSnapshotOf walks the
  whole tree under the directory when it is set, into one flat table keyed by the path
  relative to the directory watched, so a listener is named sub/old.txt and not
  old.txt; a directory's own entry in that table is its type alone, so the names below
  it are the change and the mtime a directory carries away from them is not a second
  one. watchEmitDiff names every event of such a watch rename, because FSEvents does
  not tell a name whose bytes moved from one that appeared, and names the name that is
  no longer there before the one that came -- the order a host reports a rename in. The
  walk stops 64 levels down, which is what keeps a link naming a directory above it
  from walking round forever.
